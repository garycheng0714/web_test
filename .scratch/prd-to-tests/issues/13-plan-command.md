## Agent Brief (triage)

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** Add a `plan` command that turns a PRD into a PR adding one `test-case/<id>.md` per case.

**Current behavior:**
The Test Case designer turns PRD text into a list of `Case` objects, and `render_case` renders one
`Case` into the `test-case/<id>.md` format. Nothing writes those files or opens the Gate PR: there is
no id allocation, no per-case file writer, and no git/gh orchestration for the plan stage.

**Desired behavior:**
A `plan` command reads a PRD file, runs the designer, assigns each case a `test-case-%04d` id (the
next free number after scanning `test-case/`), renders each case to `test-case/test-case-<id>.md`, and
opens **one** PR against `main` adding all of them (the human Gate). It runs **locally** (git + `gh`),
mirroring the automation entrypoint's shape (importable and CLI-runnable). It takes the base URL each
rendered file needs as a required `--base-url` argument.

Edge cases:
- `--prd` missing → print usage and exit non-zero.
- The PRD yields zero cases → write the report but open no PR; report clearly and exit non-zero.
- Branch name is unique per run, so a re-run never collides on push.
- The command must branch from an up-to-date `main` deliberately (fetch + base the new branch on
  `main`), not from whatever commit happens to be checked out.

**Key interfaces:**
- `design_test_cases(prd_text) -> list[Case]` — unchanged.
- `render_case(case, *, id, base_url) -> str` — unchanged.
- `Git` facade — in addition to its existing `set_identity`/`create_branch`/`add`/`commit`/`push`,
  it needs to fetch and start the new branch from `main`.
- `GitHub.open_pull_request` — unchanged, used for the Gate PR.
- A plan orchestrator: importable (with model, git, and gh injectable) and CLI-runnable
  (`python -m web_test.planning.entrypoint --prd <path> --base-url <url>`).
- Branch name: `plan/<prd-stem>-<UTCstamp>` (e.g. `plan/register-login-20261014T120000Z`).
- Commit and PR title: `Add test cases from <prd filename>`.
- PR body: a short summary listing the cases and the requirements each covers.
- Reuse the existing `Git`/`GitHub` facades; do **not** reuse `Publisher` (it is single-case, hardcodes
  `automation/<id>`, and re-runs the suite).

**Acceptance criteria:**
- [ ] `plan --prd <path> --base-url <url>` runs the designer and writes one `test-case/test-case-<id>.md` per case
- [ ] Ids are `test-case-%04d`, the next free numbers after scanning `test-case/`
- [ ] Exactly one PR against `main` adds all the new files
- [ ] The branch is `plan/<prd-stem>-<UTCstamp>` and the commit/PR title is `Add test cases from <prd filename>`
- [ ] The PR body lists the cases and their requirement coverage
- [ ] Missing `--prd` prints usage and exits non-zero; zero cases opens no PR
- [ ] Runnable from the command line and importable, mirroring the automation entrypoint
- [ ] Unit-tested with the model overridden and fake git/gh (no network)

**Out of scope:**
- Where `base_url` ultimately comes from (separate ticket)
- Detecting or skipping duplicate cases on a re-run
- A CI workflow for plan (local first)
- The automation side (a merged case PR → tests)

## Implementation

- `web_test/planning/cases_writer.py` — pure `render_case(case, *, id, base_url)` and
  `assign_ids(existing_names, count)` (next id = highest + 1, gaps are **not** reused), plus
  `CaseWriter(directory, base_url).write(cases) -> list[str]` (the IO seam: scans for the next free
  ids, renders, writes, and returns the file names).
- `web_test/planning/entrypoint.py` — `plan(prd_path, *, base_url, workspace, agent=design_test_cases,
  git, pr, now=None) -> PlanOutcome` (`planned`/`no_cases`/`failed`), plus `plan_branch`,
  `commit_message`, `_pr_body`, and `main()` (`--prd`, `--base-url`, `--workspace`). Reuses the
  `Git`/`GitHub` facades and the `publish.py` bot-identity/base-branch constants; does **not** use
  `Publisher`. Ordering: read PRD + run the agent, then `set_identity`/`fetch`/`create_branch(base=origin/main)`
  **before** scanning ids and writing, so ids reflect `origin/main` and the new untracked files cannot
  collide with its checkout. The PRD read and the agent run are inside the `try`, so a missing PRD or a
  model/validation error → `failed`, exit 1 (not a traceback). Zero cases → no PR and exit 1. The PR-body
  table escapes `|`/newlines via the shared `escape_cell`.
- Review fixes (post-implementation review): reordered branch-before-write (above); brought the
  PRD read + agent run into the `try`; escaped the PR-body cells; corrected doc references.
- `web_test/publishing/git.py` — added `fetch()` and `create_branch(branch, *, base=None)`, so plan
  branches from a freshly fetched `origin/main` rather than whatever is checked out.
- Tests: `tests/planning/test_cases.py` (render format + id assignment + `CaseWriter.write` round-trip
  through `CaseFile`), `tests/planning/test_plan.py` (files + one PR, no-op on zero cases, git failure,
  missing PRD, PR-body escaping, branch format, required args), and `tests/publishing/test_git.py`
  (fetch + base argv).

`uv run pytest`: 74 passed, 1 skipped. Not run live: no execution against real git/gh yet (would push a
branch and open a PR).
