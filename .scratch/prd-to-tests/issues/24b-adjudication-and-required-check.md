## Decisions / assumptions

- The original verdict comes from the existing verdict for the same cache key. The cache stores a
  structured status beside the payload; a cache miss (for example `BLOCKED`, which is never cached)
  re-runs Jev.
- An adjudicated success is never cached. The cache keeps the original verdict so a new head with
  the same content does not inherit an old approval.
- The override lives only in the check summary. No PR comment is posted, so there is no comment
  dedupe work.
- Only `NEEDS_REVIEW` and `BLOCKED` can be overridden. `PASS` is already success; `FAIL` stays a
  failure even with an approving review. Admin break-glass is a branch-protection bypass, not part
  of this workflow.
- The review must be an approving review with a non-empty reason on the current head. Reviews on an
  older commit are ignored.
- Reviewer authority requires `OWNER`, `MEMBER`, or `COLLABORATOR`; GitHub already restricts who can
  submit an approving review, so this is a defensive check.
- Re-running the original `pull_request` workflow (instead of submitting a new review) does not
  re-read old approvals in v1.
