# 22: Add deterministic checks for Test Case structure

**What to build:** Checks that need no model judgment run alongside verification and land in the
same record: front-matter and required fields, unique case identifiers, requirement IDs that exist in
the PRD, a happy-path case per requirement, and steps with non-empty actions and expected results.
Counts stay in code.

- **22a** structure checks that need only the Test Case artifact
- **22b** coverage and metadata checks that need a requirement model

## Decisions / assumptions

- The deterministic result is a separate `DeterministicOutcome`; it does not reuse the
  probabilistic `CheckOutcome`.
- A deterministic failure is `FAIL` and is not approval-overridable.
- `CHECK_SET_VERSION` is a manual cache-invalidation token for the deterministic rules.
- Unparsable artifacts keep the existing early `INVALID` path; structure checks run on a parsed
  artifact.
- 22b still needs the coverage definitions and the PRD requirement-ID convention.
