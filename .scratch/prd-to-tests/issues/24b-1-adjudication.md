# 24b-1: Adjudicate the verification check

**What to build:** When a reviewer submits an approving review with a reason on the current Test
Case PR head, re-run the `verify-test-case` check and report success for `NEEDS_REVIEW` or
`BLOCKED`, recording the original verdict, the reason, and the head SHA. `FAIL` stays a failure; a
new head gets a fresh verdict.

**Shape:**

- `Approval` (Pydantic boundary; CLI input): `state`, `reason`, `head_sha`.
  Invariants: `state == "approved"`; `reason` is non-empty after trimming; `head_sha` matches the
  head being verified. An approval that fails any invariant is ignored and the normal verdict is
  published.
- `CachedVerdict` (Pydantic boundary; the Actions cache file): `status` plus the original
  `CheckPayload`.
  Invariants: `payload.external_id` is the cache key; `status` is `PASS`, `NEEDS_REVIEW`, or `FAIL`;
  `BLOCKED` is never stored; a file in the old bare-`CheckPayload` shape is a cache miss.
- `CheckPayload` is unchanged. The override is rendered into its summary, not into a new field.
- `RunResult` (internal dataclass) gains the published status and whether an override applied.

## Decisions / assumptions

- The original verdict comes from the cache entry for the same cache key. If there is no cache entry
  (including every `BLOCKED`), run Jev again and use that status as the original.
- An adjudicated success is never cached. Keeping the original verdict in the cache is what makes a
  new head with the same content require a fresh human decision.
- The override is a summary section only. The check title becomes
  `Test Case verification: PASS (adjudicated)`; the conclusion is `success`.
- A review on a different commit is ignored without failing the workflow; the current head keeps its
  existing verdict.
- The reason is trimmed and length-limited before rendering.
- The workflow cache key gets a `v2` prefix because the cache file shape changes. Without it, an
  old-format entry would be restored forever: our loader treats it as a miss, but the workflow
  would still think the cache matched and skip the save.
- Re-reading an old approval on a plain re-run of the original `pull_request` workflow is out of
  scope for v1.

## Out of scope

- Branch protection, the shadow-to-required rollout, break-glass policy, and the live Test Case PR
  are 24b-2.
- PR comments and comment dedupe.
- Deterministic structural checks (ticket 22) and other verdict dimensions.
- Re-applying approvals when the original `pull_request` workflow is manually re-run.
