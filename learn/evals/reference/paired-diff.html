Paired diff / Metamorphic relation

沒有標準答案時，用「相關輸入」製造便宜的 oracle。

一句話

固定情境，只動一個變因，宣告一條不變式；違反就是 failure。

三種 pair

Pair改什麼不變式違反長怎樣
Paraphrase措辭事實不變矛盾
Counterfactual一個欄位只有該欄位變drift
Additive加一個需求該需求被處理遺漏

四種症狀

  • Contradiction：兩筆對同一事實給不同答案。
  • Drift：改了 A，B 也跟著變。
  • Omission：該出現的資訊消失。
  • Hallucination：多出沒人要求的事實。

餐廳訂位的例子

Pair不變式觀察到什麼背後的 failure
t-021-a / t-021-b 同一時段的可訂狀態要一致 一個說訂到，一個說客滿 客滿仍接單（false availability）
t-022-a / t-022-b 有生日需求就要有備註 一邊有慶生備註，一邊沒有 特殊需求遺漏
t-020-a / t-020-b 包場要轉業務 一邊當普通訂位，一邊轉業務 routing failure

抓到什麼、抓不到什麼

抓到抓不到
矛盾（一邊有位、一邊客滿）兩邊都錯在同一件事
遺漏（備註消失）兩邊都漏同一個需求
Drift（改人數，日期也變）需要外部 ground truth 的錯
Hallucination（多承諾窗邊）措辭差異但兩邊都合理

Diff 告訴你「去哪裡看」，不告訴你「哪一邊對」。你還是要讀 user message 或 policy 才能裁決。

對 taxonomy 的意義

不是每個 failure mode 都能用同一種 evaluator 檢查：

範圍例子Lesson 0004 的選擇
Single trace時間／日期／人數錯置、特殊需求遺漏Code evaluator 可直接比對欄位
Pairwise自相矛盾（a/b diff）需要成對資料，或多筆回覆的檢查
Policy-dependentrouting failure、false availability需要 policy 或 availability data

「自相矛盾」是偵測手法，不是 failure mode 本身。背後的 behavior 是「客滿仍接單」；命名時要寫 behavior，不是寫症狀。

推廣到真實資料

  • Paraphrase pair：同一個請求換句話說，事實應該不變。
  • Counterfactual pair：只改一個欄位（7 人→8 人），預期只有該欄位改變。
  • Same input, different seed/temperature：測模型變異。
