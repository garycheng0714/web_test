定義

Trace一次完整執行的紀錄：輸入、中間步驟、工具呼叫、最終輸出。
Eval一個「行為是否成立」的檢查，回傳 Pass 或 Fail。
Failure mode一種可命名的錯，附一個可觀察的例子。
Error analysis人看 traces、替錯誤命名，產出 failure mode 清單。
Golden set帶人類標籤、用來驗證 evaluator 的固定資料集。
TPR / TNR人類說 Pass 時 judge 也說 Pass 的比率／人類說 Fail 時 judge 也說 Fail 的比率。
Data leakage把 dev/test 的例子放進 judge prompt 的 few-shot，讓分數虛高。

常用數字

Error analysis 飽和約 100 筆 traces；新 traces 不再帶出新 failure mode。
Judge 驗證資料約 50 Pass + 50 Fail；低於 60 筆信賴區間會很寬。
Judge 對齊目標TPR 與 TNR 都 > 90%；最低可接受 > 80%。
資料切分Train 10–20%（few-shot 來源）、Dev 40–45%、Test 40–45%。

Rogan-Gladen 修正

Judge 在未標註資料上算出的 Pass 比率是有偏的：容易心軟的 judge 會把 false positive 算進 Pass。用 TPR／TNR 反推真實通過率：

theta_hat = (p_obs + TNR - 1) / (TPR + TNR - 1)

p_obs = judge 在未標註資料上說 Pass 的比率。raw pass rate = (TP + FP) / N，不是 accuracy (TP + TN) / N；corrected 修正的是 true pass rate。

J = TPR + TNR - 1（Youden index）。J=1 完美、J=0 沒有資訊、J<0 比亂猜還糟。

Var(theta_hat) ≈ Var(p_obs) / J^2；CI 寬度約正比於 1 / (J * sqrt(n))。

95% CI 是程序覆蓋率：重複抽樣下約 95% 的區間會涵蓋真值；不是「真值有 95% 機率在區間內」。

[5%, 95%] 不能決策；[49%, 51%] 可以。
