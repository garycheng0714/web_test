為什麼 raw accuracy 會騙人

假設 90% 的 traces 是 Pass。一個永遠說 Pass 的 judge 有 90% accuracy，但 TNR = 0：它抓不到任何 failure。

所以我們看兩個數字：

  • TPR：人類說 Pass 時，judge 也說 Pass 的比率。
  • TNR：人類說 Fail 時，judge 也說 Fail 的比率。
Human PassHuman Fail
Judge PassTPFP
Judge FailFNTN
 
TPR = TP / (TP + FN)
TNR = TN / (TN + FP)

資料切分

Split大小用途規則
Train10–20%few-shot 範例來源只用清楚 Pass／Fail；不能再進 dev／test
Dev40–45%反覆迭代 prompt可以一直看、一直改
Test40–45%最終量測只跑一次；看過就不能再調

把 dev／test 的例子放進 judge prompt 就是 data leakage，分數會虛高。

目標：TPR 與 TNR 都 > 90%；最低可接受 > 80%。

為什麼要修正通過率

Judge 不是完美的檢驗。它會漏抓（false negative），也會誤放（false positive）。所以它在未標註資料上數出來的 Pass 比率，不是產品真正的好壞，而是被 judge 自身偏誤扭曲過的數字。

Raw pass rate 不是 accuracy

raw pass rate = (TP + FP) / N
accuracy      = (TP + TN) / N

例：10,000 筆，judge 說 8,000 筆 Pass。假設其中 7,000 真 Pass、1,000 真 Fail（FP）；另外 2,000 真 Fail 正確判 Fail、1,000 真 Pass 誤判 Fail（FN）：

真的 Pass真的 Fail
Judge Pass7,0001,000
Judge Fail1,0002,000
  • raw pass rate = 8,000 / 10,000 = 80%
  • accuracy = (7,000 + 2,000) / 10,000 = 90%

所以「80%」不是 accuracy，是 pass rate。Rogan-Gladen 修正的是 true pass rate／success rate，不是「corrected accuracy」。

偏差可能往上，也可能往下

容易心軟的 judge（高 TPR、低 TNR）會把不合格的答案判成 Pass，讓 raw pass 偏高；漏抓多（低 TPR）則讓 raw pass 偏低。淨效果取決於 TPR／TNR 與真實通過率。我們的模擬就是低估：FN 多於 FP，所以 raw 0.73 < true 0.77。

Rogan-Gladen 是流行病學用來修正「不完美檢驗試劑」的經典方法：從有偏的觀測值反推真實比率。

theta_hat = (p_obs + TNR - 1) / (TPR + TNR - 1)

其中 p_obs 是 judge 在未標註資料上說 Pass 的比率；TPR／TNR 是你在 test set 上量到的。

例：TPR = 0.92、TNR = 0.88、p_obs = 0.80 → (0.80 + 0.88 − 1) / (0.92 + 0.88 − 1) = 0.68 / 0.80 = 0.85。

分母 TPR + TNR − 1 有一個名字：Youden index，記作 J。它衡量 judge 的鑑別力，不是只看 TPR 或 TNR 單邊。

為什麼 J 越小，CI 越寬

J例子意義
1.0TPR=1.0, TNR=1.0完美；corrected = p_obs
0.7TPR=0.9, TNR=0.8可用，但雜訊被放大
0.0TPR=0.5, TNR=0.5沒有資訊；估計未定義
< 0TPR=0.5, TNR=0.4比亂猜還糟；不要用

反例：TPR=0.99、TNR=0.02 → J=0.01。TPR 很高，但幾乎沒有鑑別力；所以不能只看單邊。

修正後的估計是線性的：

theta_hat = (p_obs + TNR - 1) / J

固定 TPR／TNR 時，變異數被 1/J² 放大：

Var(theta_hat) ≈ Var(p_obs) / J^2

而 Var(p_obs) = p(1-p)/n，所以 CI 寬度大約正比於：

1 / (J * sqrt(n))

這就是「訊號被稀釋」：J 越小，同樣的觀測波動被放大 1/J² 倍。J=0 時估計不存在，CI 無限寬；J<0 表示 judge 比亂猜還糟，修正公式會失真，不要用。

Bootstrap 另外還會把 TPR／TNR 本身的估計誤差算進去；所以 test set 太小，CI 也會寬。

CI 是什麼，以及寬度為什麼重要

CI（Confidence Interval，信賴區間）是根據樣本算出的數值範圍，用來表示估計值有多精準。

公式與方法查表：CI methods 備忘。

95% CI 的正確讀法是：如果重複抽樣與估計很多次，約 95% 的區間會涵蓋真值。不是「真值有 95% 的機率落在這個區間」；真值是固定的，隨機的是區間。

常見誤讀

「我們有 95% 的信心，真值落在 5% 到 95%」是簡寫。精確說法是：這個估計程序在重複抽樣下，約 95% 的區間會涵蓋真值。

同樣是 50% 的估計，CI 寬度決定它能不能拿來做決策：

95% CI寬度實務解讀決策價值
[5%, 95%]90 個百分點J 太低或樣本太少，幾乎全是雜訊不能拍板
[49%, 51%]2 個百分點judge 可靠、樣本充足可以報告
[65%, 89%]24 個百分點本課模擬的結果；方向有了，但還不夠精準僅供參考

寬度主要來自三個地方：

來源影響
J = TPR + TNR − 1J 越小，誤差被 1/J² 放大
Test set 大小TPR／TNR 本身估計不穩，CI 變寬
Production 樣本數 np_obs 的抽樣誤差，CI 變寬

所以 CI 寬度大致正比於 1 / (J * sqrt(n))。寬到像 [5%, 95%] 時，它不是「保守」，是「沒有資訊」。

動手跑

python3 learn/evals/toy/validate.py

它模擬一個已知 TPR／TNR 的 judge，切分資料，量 dev／test，然後修正 production 通過率。預設輸出：

simulated judge: TPR=0.90 TNR=0.85
splits: train=30 dev=90 test=80
dev: n=90 TP=42 FN=3 TN=39 FP=6 TPR=0.93 TNR=0.87
test: n=80 TP=36 FN=4 TN=32 FP=8 TPR=0.90 TNR=0.80

production: n=500 raw pass=0.73
corrected=0.76  95% CI=[0.65, 0.89]
true rate (simulation only)=0.77

（上面是原始 0.90／0.85、200 筆的輸出；你若改過常數，數字會不同。）

怎麼讀：

  • Test TNR 0.80 比目標 0.85 低；80 筆還是有抽樣雜訊。
  • Raw pass 0.73 低估了真實的 0.77；修正後 0.76，比較接近。
  • CI [0.65, 0.89] 很寬，因為分母 0.90 + 0.80 − 1 = 0.70，誤差被放大。

500 筆拆解

模擬的 500 筆裡，真實通過率是 0.77（約 385 Pass、115 Fail）。Judge 的 TPR=0.90、TNR=0.85，大約會得到：

真的 Pass（約 385）真的 Fail（約 115）
Judge PassTP ≈ 347FP ≈ 17
Judge FailFN ≈ 38TN ≈ 98

raw pass = (TP + FP) / 500 ≈ 364 / 500 ≈ 0.73。它比真實的 0.77 低，因為 FN（約 38）多於 FP（約 17）。

用 test set 的 TPR=0.90、TNR=0.80 修正：

corrected = (0.73 + 0.80 - 1) / (0.90 + 0.80 - 1)
          = 0.53 / 0.70
          = 0.76

0.76 是估計的真實通過率；0.73 是 judge 的原始輸出；0.77 是模擬才知道的答案。

不要從單次 run 推論

CI 本身是隨機的。改了 TPR／TNR 或 N 之後，單次 run 的 CI 變窄或變寬，可能只是抽樣波動。要判斷 N 的影響，請跑多個 seed，比較平均寬度；expected width 約正比於 1 / (J * sqrt(n))。

多 seed 的結果

python3 learn/evals/toy/validate_many.py 會跑 20 個 seed，比較 200 筆與 100 筆（目前 TPR=0.95／TNR=0.80）：

200 labels: CI width 0.144 ± 0.049, coverage 0.80
100 labels: CI width 0.174 ± 0.109, coverage 0.50

100 筆的 CI 平均更寬、變異也更大，符合 1/(J*sqrt(n))。Coverage 低於 95% 不是矛盾，是提醒：CI 是近似，test set 太小或 bootstrap 忽略 production 抽樣時，它會低估不確定性。

你的 tone judge

5／5、TPR = TNR = 1.00，但 n = 5。那不是驗證，是 spot check。這一課的 80 筆 test 都還會晃，5 筆不能宣稱對齊。

要真的驗證，用 toy/tone_labels.json 對 44 筆標 binary Pass／Fail；空白代表未標。這個 toy 的 Fail 太少，還達不到 50／50，先把它當 labeled-data 缺口。

  1. 先跑一次預設值，記下 test TPR／TNR、corrected、CI。
  2. 把檔案上方的 TPR 改成 0.95、TNR 改成 0.80，重跑。觀察 corrected 與 CI 怎麼變。
  3. 把 N_PASS／N_FAIL 改成 50／50，重跑。觀察 CI 變寬多少。
  4. 跑 python3 learn/evals/toy/validate_many.py，看 20 個 seed 下 200 筆與 100 筆的 CI 寬度分布。
  5. 在 NOTES.md 寫三行：raw vs corrected、CI、你覺得這個 judge 夠不夠好。

實務提醒

  • Pin judge 的模型版本（dated snapshot），不要用浮動 alias。
  • 換模型、改 prompt、改 few-shot 後要重新驗證。
  • 標籤找一位可信的 domain expert；不要外包給不懂 domain 的人。
  • TPR 對 CI 的影響比 TNR 大：分母變大，誤差被縮小。
  • 只有 point estimate 不夠；一定要報 CI。
