Harness：模型之外的那一圈

這一課只教你一件事：說出 harness 與 capability 的關係，並指出你的 qa_designer 如何用 Skills 把領域知識按需載入。

學完你能做到

打開 web_test/qa_designer.py，你能指出哪一行是 harness、哪一行是 core，並講出這個 agent 在第一個模型回合「看到」什麼、load_capability 之後又多出什麼。

先一句話定義 harness

harness 是「模型之外、把它從一個語言模型變成一個 agent」的那一圈：agent loop、工具、以及 context 管理。

Pydantic AI 每個 agent 都已經有一個「輕量 harness」：型別化的 agent loop、任意模型、你自己的工具、結構化輸出。對簡單的 agent 這樣就夠了。

Pydantic AI Harness（套件名 pydantic-ai-harness）就是官方把「重 harness」需要的那一圈補齊：workspace、planning、memory、sub-agents、context 管理、durable execution。

一切都是 capability

Harness 裡沒有魔法，整個套件只有一個原語：capability——一個自足的 agent 行為單位，可自帶 instructions、tools、settings、hooks，丟進任何 agent 的 capabilities=[...]。

連完整 agent 也是 capability 疊出來的：Coder 是一個 FileSystem＋Shell＋RepoContext＋SubAgents＋… 的組合——「怎麼裝上去，就能怎麼拆下來」。

Harness 與核心 Pydantic AI 的分界是機械性的、不是成熟度分級：核心供應「需要模型或框架支援」的 capability（thinking、MCP、web search、provider-native 工具）；harness 供應其餘 30 多個，獨立成套件，好在 Pydantic AI 保持精簡的同時，讓 capability 快速演進。

完整分群速查見 Harness capabilities 速查。

按需載入：為什麼要 defer

如果你的領域知識只在少數回合才用得到，就不該塞進每一回合的 prompt。Pydantic AI 的做法是 progressive disclosure：

初始 prompt ← 只有 catalog：每個 deferred capability 的 id（＋description） │ ▼ 模型判斷需要某個領域 呼叫 load_capability("...") ← 框架代管的工具 │ ▼ 該 capability 的 instructions／tools 才進來

作法是把 capability 標上 defer_loading=True 並給穩定 id；只要 agent 有任何 deferred capability，框架就自動加上 load_capability。規則簡單：大部分回合不需要的資訊，就不要預設擺在 prompt 裡。

Skills：把領域 SKILL.md 變成 deferred capability

Skills 是 harness 裡專門做這件事的 capability。它把你的 Agent Skill（一個含 SKILL.md 的資料夾）變成一個 deferred capability。

重點行為
指到哪一層指向 library 目錄，不是單一 skill；它掃描直接子目錄，每個有 SKILL.md 的資料夾算一個 skill
模型先看到什麼各 skill 的 name 與 description；有用時才呼叫 load_capability 取回本文
載入什麼只載 SKILL.md；不列舉／讀取／執行 references/、assets/、scripts/
挑選 skillinclude=[...] 或 exclude=[...]（不可同時用）；未選中者連 frontmatter 都不解析
workspace必需；沒有 workspace 的 run 會在起頭就失敗

注意：include/exclude 控制的是「catalog 曝光」，不是檔案權限或存取邊界。只從你信任的來源載入 library。

動手：追一次你的 run

這是 web_test/qa_designer.py 的核心。先別往下滑，用你的話回答兩個問題，再展開對答案。

1  SKILL_LIBRARY = REPO_ROOT / ".agents" / "libraries" / "test_case_designer"
2  SKILL_NAME = "qa-test-case-generation"
3
4  agent = Agent(
5      model or resolve_model(),
6      name="test_case_designer",
7      output_type=QaReport,
8      instructions=INSTRUCTIONS,
9      capabilities=[
10         Skills(
11             str(SKILL_LIBRARY),
12             include=[SKILL_NAME],
13             workspace=LocalWorkspaceBackend(str(REPO_ROOT)),
14         )
15     ],
16 )
Q1 · turn 1，模型看到 qa-test-case-generation 的內容了嗎？

沒有。它只看到 catalog：這個 skill 的 name 與 description（來自 SKILL.md frontmatter），以及框架加的 load_capability 工具。本文還沒進來。

Q2 · Skills(...) 的 str(SKILL_LIBRARY) 指向哪一層？

指向 library（.agents/libraries/test_case_designer），不是單一 skill。它掃描該目錄的直接子目錄，找到 qa-test-case-generation/SKILL.md，並用 include=[SKILL_NAME] 把 catalog 限定成只有這一個。

Q3 · 模型要怎麼才拿得到 skill 的完整指示？

呼叫 load_capability("qa-test-case-generation")。這正是 INSTRUCTIONS 裡第一步要求它做的事。回傳內容是 # Skill: qa-test-case-generation 標題加上 Markdown 本文。

想親眼確認它跑得動（用 TestModel，不呼叫真模型）：

uv run pytest tests/test_qa_designer.py -q

可選小實驗：在 design_test_cases 內把 agent 的初始能力 catalog 印出來，觀察 load_capability 出現、而 skill 本文尚未出現。

檢索練習

先別回頭看。努力回想。

Q1. 在 Pydantic AI 裡，capability 是什麼？

  • 正確。capability 自帶 instructions／tools／settings／hooks，丟進 capabilities=[...] 即可；連完整 agent 都是它的組合。

Q2. 把領域知能標成 defer_loading=True，主要為了什麼？

  • 正確。大部分回合用不到的資訊不預載；模型先看 catalog，需要時才用 load_capability 取回。

Q3. Skills(...) 的第一個參數要指向哪一層？

  • 正確。它掃描該目錄的直接子目錄，每個含 SKILL.md 的資料夾算一個 skill；指到單一 skill 會錯。
