The Main Flow：idea → ship

這一課只教你一件事：把手上任何任務放上主流程，並說出下一步該用哪個 skill。

學完你能做到

看著我們的功能——「把自然語言任務轉成 Playwright TS 測試的 agent」——你能指出它現在在流程的哪一格，以及下一個要打的指令是 /to-spec。

主流程只有一條

這套流程的核心是一個路線：從一個模糊的想法，走到可出貨的程式。中間有幾個關卡，每個關卡由一個 skill 負責。先感受整體，再記細節。

idea │ ▼ grill-with-docs 訪談收斂，順手寫 CONTEXT.md / ADR │ ├─ 唯有「跑起來看」才能回答的問題？ → handoff → prototype → handoff │ ▼ 是多 session 的大工作嗎？ ├─ 是 → to-spec → to-tickets → implement（每票一個 fresh context） └─ 否 → implement（就在同一段 context 做完） │ └─ 內部驅動 tdd（紅→綠）→ code-review → commit

完整版（含 on-ramps 與 skill 分類）在 主流程速查。

先分清楚兩種 skill

類型誰能觸發角色
User-invoked只有你（打 /to-spec）編排流程
Model-invoked你或 agent 皆可可重用的紀律（tdd、seam 設計…）

記住一句：流程 skill 可以被模型載入的參考 skill 支援，但流程 skill 之間不互相呼叫。

套到我們的功能

我們已經在對話中把需求談清楚了（等於做過 grill），而且這件事跨多個 session。所以現在的位置是：

grill（已完成） ▼ 【你現在在這裡】→ to-spec ← 下一步 to-tickets implement（逐票）

檢索練習

先別往上看，憑記憶作答。答錯沒關係——努力的回想才會留下長期記憶。

Q1. 需求已談清楚、且要跨多個 session，主流程的下一步是哪一個？

  • 正確。to-spec 把已談定的內容收斂成 spec，發佈到 issue tracker，之後才 to-tickets。

Q2. 哪一項屬於 on-ramp（不是主流程本身）？

  • 正確。triage 是處理「別人丟來的 issue / 外部 PR」的 on-ramp，處理完會匯入主流程。

Q3. 接近 smart zone 上限、工作還沒做完，該怎麼做？

  • 正確。在階段邊界 clear / compact，讓下一個階段在 smart zone 內進行；implement 尤其要在新 context。
